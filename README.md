# Система управления торговыми стендами

## Назначение

Приложение для учёта торговых стендов и управления их бронированием.
Консольная версия (ПР3) дополнена веб-интерфейсом на Django (ПР5).

Приложение позволяет:

* просматривать стенды в браузере;
* просматривать информацию о конкретном стенде;
* проверять доступность стенда на выбранную дату;
* просматривать список бронирований в браузере;
* просматривать информацию о конкретном бронировании;
* (консоль) добавлять стенды и арендаторов, искать и фильтровать стенды,
  создавать и отменять бронирования;
* хранить данные между запусками приложения.

## Используемые технологии

* Python 3;
* Django 5.2 – веб-фреймворк;
* HTML – разметка веб-страниц;
* CSS и Bootstrap 5.3 (через CDN) – оформление страниц;
* pytest – автоматизированные тесты;
* flake8 – проверка качества кода.

## Целевая аудитория

Организаторы ярмарок и выставок, а также арендаторы, которым нужно
бронировать торговые стенды на определённые даты.

## Предметная область

Основные объекты: стенд, арендатор (пользователь), бронирование.

Арендатор может бронировать стенды на определённые даты. Один стенд не
может иметь два активных бронирования на одну и ту же дату. Отменённое
бронирование не блокирует стенд и позволяет создать новое на эту дату.

## Основные сущности

### Stand – торговый стенд

* атрибуты: `id`, `name`, `area` (площадь, кв.м.), `stand_type`;
* методы: `validate_area()`, `from_data()`, `to_data()`, `__str__()`.

### User – арендатор

* атрибуты: `id`, `name`, `email`;
* методы: `from_data()`, `to_data()`, `__str__()`.

### Booking – бронирование

* атрибуты: `id`, `stand` (объект `Stand`), `booking_date`,
  `user` (объект `User`), `is_cancelled`;
* методы: `cancel()`, `is_active()`, `__str__()`.

`Booking` хранит ссылки на объекты `Stand` и `User`, поэтому в веб-слое
доступны `booking.stand.name` и `booking.user.email`.

## Страницы веб-интерфейса

| URL | View-функция | Назначение |
|-----|--------------|------------|
| `/` | `homepage.views.index()` | главная: описание и навигация |
| `/stands/` | `stands.views.stands()` | список стендов из `data/stands.json` |
| `/stands/<int:stand_id>/` | `stands.views.stand_detail()` | карточка стенда и его доступность |
| `/bookings/` | `bookings.views.bookings()` | список бронирований из `data/bookings.json` |
| `/bookings/<int:booking_id>/` | `bookings.views.booking_detail()` | карточка бронирования |

Страница стенда принимает необязательный GET-параметр `date`
(`/stands/1/?date=2026-10-15`) и показывает доступность на эту дату;
без параметра – на сегодня. Неверная дата заменяется сегодняшней
с предупреждением.

Если стенд или бронирование с указанным идентификатором не найдены,
страница возвращает код статуса 404. Для любого несуществующего адреса
подключён собственный обработчик `handler404`
(`homepage.views.page_not_found()`).

Общий HTML-каркас (кодировка, Bootstrap 5.3, навигация) формирует функция
`page()` в `homepage/views.py`; остальные приложения её импортируют.
Все значения из данных экранируются через `django.utils.html.escape`.

## Основные операции

### Используется в веб-интерфейсе (ПР5)

* просмотр списка стендов;
* просмотр информации о стенде;
* проверка доступности стенда на дату;
* просмотр списка бронирований;
* просмотр информации о бронировании.

### Отложено до следующих работ

Реализовано в ПР3 и работает в консольной версии. В вебе появится вместе
с формами и POST-запросами:

* добавление стенда и пользователя;
* поиск стенда по названию;
* фильтрация стендов по площади и сортировка;
* создание и отмена бронирования.

## Хранение данных

Данные хранятся в JSON-файлах:

* `data/stands.json`;
* `data/users.json`;
* `data/bookings.json`.

При загрузке данные преобразуются в объекты `Stand`, `User` и `Booking`,
при сохранении – обратно в JSON. Бронирование связано со стендом и
пользователем через `stand_id` и `user_id`. Файлы содержат тестовые
данные для демонстрации.

## Структура проекта

```text
проект фреймворк/
│
├── README.md
├── requirements.txt
├── manage.py
├── main.py                 # консольная версия (ПР3)
├── storage.py
├── utils.py
│
├── tradestands/            # конфигурация Django-проекта
│   ├── settings.py
│   ├── urls.py             # маршрутизация верхнего уровня
│   ├── dataset.py          # загрузка JSON-данных для view-функций
│   ├── asgi.py
│   └── wsgi.py
│
├── homepage/               # приложение: главная, page(), страница 404
├── stands/                 # приложение: стенды
├── bookings/               # приложение: бронирования
│   (в каждом: views.py, urls.py, tests.py, admin.py, models.py)
│
├── models/                 # классы предметной области (ПР3)
│   ├── stands.py
│   ├── users.py
│   └── bookings.py
│
├── data/                   # JSON-хранилище
├── tests/                  # pytest-тесты ПР3
└── legacy/                 # модули ПР2 (словари), не используются
```

Отдельное Django-приложение для пользователей не создаётся: Django
предоставляет встроенную модель `User` (`django.contrib.auth`), а модуль
`models/users.py` остаётся частью консольной версии.

Модули ПР2 `stands.py` и `bookings.py` перенесены из корня в `legacy/`,
так как совпадали по имени с Django-приложениями `stands` и `bookings`.

## Запуск приложения

Установка зависимостей (в виртуальном окружении):

```text
pip install -r requirements.txt
```

Веб-версия (Django):

```text
python manage.py migrate
python manage.py runserver
```

После запуска открыть в браузере `http://127.0.0.1:8000/`.

Консольная версия (сохранена):

```text
python main.py
```

## Текущее состояние и план развития

Реализовано (ПР5):

  (`homepage`, `stands`, `bookings`);

* переход на шаблоны (`templates/`) и отказ от функции `page()`;
* формы создания бронирований и редактирования стендов;
* использование отложенной логики ПР3;
* аутентификация, API, контейнеризация, CI/CD.
