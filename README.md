# Система управления торговыми стендами

Система учёта торговых стендов и их бронирования на Python с веб-интерфейсом на Django.

## 1. Назначение проекта

Приложение для управления торговыми стендами и их бронированием. Проект позволяет хранить сведения о стендах, арендаторах и бронированиях, выполнять основные операции с этими объектами и просматривать информацию через веб-интерфейс Django.

Проект развивается поэтапно: консольная версия (ПР3) дополнена веб-интерфейсом (ПР5), который в ПР6 переведён на систему шаблонов Django.

## 2. Используемые технологии

- Python 3;
- Django 5.2;
- Django Template Language (DTL);
- HTML5;
- CSS3;
- JavaScript;
- Bootstrap 5.3 (через CDN);
- JSON для хранения данных;
- Git;
- pytest;
- flake8.

## 3. Предметная область

В системе используются три основные сущности:

- Стенд (`Stand`) – идентификатор, название, площадь, тип;
- Арендатор (`User`) – идентификатор, имя и email;
- Бронирование (`Booking`) – идентификатор, стенд, арендатор, дата бронирования и признак отмены.

Для предметной области реализованы собственные Python-классы (пакет `models/`). Бронирование хранит ссылки на объекты `Stand` и `User`. Один стенд не может иметь два активных бронирования на одну дату; отменённое бронирование стенд не блокирует.

На текущем этапе данные хранятся в JSON-файлах. Django ORM и база данных приложения пока не используются.

## 5. Веб-интерфейс

Веб-часть приложения реализована на Django. Основные страницы:

| URL | Имя маршрута | Назначение |
|-----|--------------|------------|
| `/` | `homepage:index` | главная страница |
| `/stands/` | `stands:list` | список стендов |
| `/stands/<int:stand_id>/` | `stands:detail` | страница стенда и проверка доступности на дату (`?date=ГГГГ-ММ-ДД`) |
| `/bookings/` | `bookings:bookings` | список бронирований |
| `/bookings/<int:booking_id>/` | `bookings:detail` | страница бронирования |

Если стенд или бронирование не найдены, возвращается страница с кодом 404; для несуществующих адресов подключён `handler404` (шаблон `templates/404.html`).

HTML в Python-коде веб-представлений не формируется. Функция `page()` из ПР5 удалена. Представления находят данные, готовят словарь контекста и вызывают `render()`.

## 6. Django Template Language

### Базовый шаблон

Общая структура страниц находится в `templates/base.html`: объявление документа, подключение Bootstrap и собственного CSS, логотип, навигация, подвал, подключение JavaScript. Дочерние страницы используют наследование:

```text
{% extends "base.html" %}
```

и переопределяют блоки `{% block title %}` и `{% block content %}`.

### Включаемые шаблоны

Повторяющиеся фрагменты вынесены в отдельные шаблоны и подключаются через `{% include %}`:

- `templates/includes/navigation.html` – навигация сайта (в `base.html`);
- `stands/includes/stand_card.html` – карточка стенда (в списке стендов);
- `bookings/includes/booking_status.html` – статус бронирования (в списке и на странице бронирования).

### Контекст, циклы и условия

Данные передаются в шаблоны через контекст, например:

```python
context = {"stands": stands_list}
return render(request, "stands/stand_list.html", context)
```

Для списков используется `{% for %}` с веткой `{% empty %}` (пустые коллекции), для различных состояний – `{% if %}` (активное и отменённое бронирование, найденный и не найденный объект, доступность стенда).

## 7. Фильтры шаблонов

- `{{ stands|length }}`, `{{ bookings|length }}` – количество элементов;
- `{{ stand.name|default:"Без названия" }}` – значение по умолчанию;
- `{{ stand.area|floatformat:1 }}` – формат площади;
- `{{ check_date|date:"d.m.Y" }}` – формат даты проверки доступности.

Фильтры используются только для представления данных и не содержат бизнес-логики. Дата бронирования в JSON хранится строкой и выводится без преобразования.

## 8. URL-маршрутизация

Ссылки в шаблонах формируются через `{% url %}`, жёстко заданных адресов в HTML нет. У каждого приложения задан `app_name` (пространство имён):

```text
{% url 'stands:list' %}
{% url 'stands:detail' stand.id %}
{% url 'bookings:bookings' %}
{% url 'bookings:detail' booking.id %}
{% url 'homepage:index' %}
```

## 9. Статические файлы

Статические файлы проекта находятся в `homepage/static/homepage/`:

- `css/style.css` – собственные стили (карточки стендов, статусы бронирований, логотип, подвал);
- `img/logo.png` – логотип;
- `js/main.js` – вывод текущего года в подвале.

В шаблонах используется `{% load static %}` и `{% static 'homepage/css/style.css' %}`. Bootstrap сохранён для базовой вёрстки. Проверить поиск файла: `python manage.py findstatic homepage/img/logo.png`.

## 10. Хранение данных

Данные хранятся в JSON-файлах `data/stands.json`, `data/users.json`, `data/bookings.json`. Загрузку выполняет модуль `storage.py`, предметные объекты создаются из классов пакета `models/`. Бронирование связано со стендом и арендатором через `stand_id` и `user_id`. Django ORM на текущем этапе не используется.

## 11. Основные модули

- `storage.py` – загрузка и сохранение данных (JSON ↔ объекты);
- `models/` – классы `Stand`, `User`, `Booking` и функции работы с ними;
- `main.py`, `utils.py` – консольная версия приложения;
- `tradestands/dataset.py` – загрузка всех данных для веб-представлений;
- `homepage/views.py`, `stands/views.py`, `bookings/views.py` – веб-представления.

## 13. Запуск проекта

Установка зависимостей (в виртуальном окружении):

```text
pip install -r requirements.txt
```

Веб-версия:

```text
python manage.py migrate
python manage.py runserver
```

После запуска открыть `http://127.0.0.1:8000/`. Консольная версия: `python main.py`.

## 14. Текущее состояние проекта

Реализовано:

- предметные классы `Stand`, `User`, `Booking`, консольный интерфейс, хранение в JSON;
- Django-проект `tradestands` и приложения `homepage`, `stands`, `bookings`;
- Django Template Language: базовый шаблон, наследование, блоки, включаемые шаблоны;
- передача данных через контекст, циклы и условия, фильтры;
- именованные URL и пространства имён;
- статические CSS, JavaScript и изображение, собственное оформление;
- тесты предметной области и веб-страниц.

Формы Django, модели Django ORM и работа с базой данных в текущей версии не реализованы.
